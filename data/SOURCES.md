# Data provenance

The primary card transaction stream is generated by this repository. Its tokens and identities are fictitious; no PAN, bank account, or customer record is used.

The public benchmark is [OpenML dataset 43627](https://www.openml.org/search?id=43627&type=data), an anonymized two-day credit-card fraud dataset originally attributed to the Machine Learning Group at Université Libre de Bruxelles. Its [OpenML API metadata](https://www.openml.org/api/v1/json/data/43627) lists the license as “Database: Open Database, Contents: Database Contents,” 284,807 rows, 492 fraud labels, and a public Parquet URL. `Time` is seconds from the first transaction; `V1`–`V28` are anonymized PCA components; `Amount` and `Class` are the other fields. We download it locally to `data/raw/openml_43627.parquet`, which is ignored by git. The data is **not** redistributed in this repository. The public benchmark is evaluated separately from the synthetic feature model because it does not contain card/device/merchant IDs or the same online feature contract.

The locally cached Parquet file measured SHA-256 `91650a62cb263b7fd76610a8f2fa55c4e861033b56dd51ed22d707838c95e0cf` on 20 October 2026. The original download command was not preserved, so this hash identifies this local copy rather than proving its complete acquisition history. Do not claim model transfer from synthetic to public data; the feature spaces differ.

## Synthetic settlement fixture

`bench/settlement_fixture/` is a second, separately generated settlement data set. It is **synthetic**: every capture ID, merchant and amount was invented by `fraud/src/payguard_fraud/settlement_fixture.py` with seed `20261020`, and the files were generated on 20 October 2026. It is not a real card-network file and is not independent real-world evidence.

It is independent of the earlier [`bench/settlement_sample.csv`](../bench/settlement_sample.csv) in one specific sense: the generator writes network rows from its own case table, not from PayGuard's `/v1/settlements/sample` endpoint or any existing ledger. The same author wrote the generator and the reconciler, so the labels are an executable specification, not an outside oracle.

| File | Who reads it | Contents |
|---|---|---|
| `ledger_plan.csv` | Kotlin test harness only | Captures to book through the API, plus injected journal faults (`none`, `missing`, `duplicate`, `wrong_currency`, `amount_off`) |
| `network.csv` | The reconciler | Network-shaped `capture_id,amount_minor,currency` rows |
| `labels.csv` | The Python scorer only | Expected status for each network row, each capture omitted by the network, and each capture's journal audit |
| `reconciler_output.json`, `score.json` | People | The 20 October harness output (copied from `build/settlement-fixture/`) and its score against `labels.csv`: 105/105 correct |
| `provenance.json` | People and the harness (date and fixture ID only) | Seed, generator SHA-256, case counts, label counts and SHA-256 of the three CSV files |

Regenerate with `cd fraud && PYTHONPATH=src .venv/bin/python -m payguard_fraud.settlement_fixture generate --out ../bench/settlement_fixture`. The same seed and generator source produce byte-identical CSV files; any change to the generator changes `generatorSha256`.
